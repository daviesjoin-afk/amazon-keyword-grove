# 广告建议规则优化回滚预案

## 1. 目的与适用范围

本预案用于“广告建议规则、词根推导与双重审核优化”上线前、灰度期间和正式运行后的故障恢复。目标是在不丢失关键词、来源 ASIN、指标历史和人工锁定结果的前提下，恢复到上一版稳定规则。

本预案不允许通过删除整个工作区、删除数据库目录或覆盖未验证的备份来恢复。任何不可逆操作都必须在备份校验完成后执行，并优先采用可恢复的改名或隔离方式。

## 2. 回滚设计约束

1. 规则改造使用独立 Git 分支和独立 Pull Request；未合并的实现不直接写入 `main`。
2. 数据库迁移只允许新增可空字段、索引或非破坏性元数据；不得删除旧字段、重写人工动作或删除历史快照。
3. 新规则使用显式版本号和功能开关，例如 `ad_rules_v2`；关闭开关后由 v1 继续生成建议。
4. v2 先影子计算并保存比较结果，再逐产品启用，不直接替换 v1 导出结果。
5. 每条建议保存规则版本、动作来源和证据；回滚代码后，旧版本能够忽略新增字段并读取旧动作。
6. 语义审核失败、响应缺失或动作非法时，保持待审核，不自动降级为投放或否词。

## 3. 上线前备份清单

在任何数据库迁移、规则重算或灰度开关变更前，记录以下信息：

- 当前 Git commit、分支、应用版本和规则版本；
- 数据库绝对路径、文件大小、修改时间；
- SQLite 是否启用 WAL；
- 产品数量、每个产品关键词数量、来源 ASIN 数量；
- 每个产品已审核/待审核数量；
- 精准、广泛、否定精准、否定词组和观察数量；
- 人工锁定记录数量；
- 当前选中产品 ID（如前端有持久化选择）；
- 当前 AI 配置是否启用，仅记录是否和脱敏后的模型标识，不记录 API Key。

备份至少包括：

1. SQLite 主数据库文件；
2. 数据库对应的 `-wal` 和 `-shm` 文件（存在时）；
3. 当前版本的迁移记录和规则配置；
4. 脱敏后的统计快照，用于回滚后的数量核对。

备份必须存放在明确的备份目录，并完成文件存在性、大小和 SQLite 可读性校验。校验通过前不得覆盖或删除原数据库。

## 4. 回滚触发条件

满足任一条件即可暂停灰度并评估回滚：

- 应用无法启动、迁移失败或健康检查失败；
- 关键词总量、来源 ASIN 数量或审核总数与基线不一致；
- 人工锁定动作、备注或分类发生非预期变化；
- 同一关键词出现多个最终动作且未被标记为冲突；
- 低覆盖率词（例如 `3/20`、`5/20`）进入精准或广泛；
- 广泛词条超过产品上限仍被直接导出；
- 有效产品组合被否定词组拦截；
- AI 请求数、批次数或费用异常增长；
- 增量审核重复处理已完成记录，或刷新后审核状态丢失；
- 导入成功但产品状态、关键词数量或广告建议为空；
- 回归测试、前端构建、后端编译或脱敏扫描失败。

## 5. 回滚级别

### Level 1：关闭 v2 功能开关

适用：数据结构正常，仅新规则结果不符合预期。

步骤：

1. 停止新的全量重算和增量审核任务；
2. 将规则开关切回 v1；
3. 保留 v2 影子结果和冲突证据，不删除；
4. 用 v1 生成新的待审批草稿；
5. 核对关键词总量、人工锁定数量和导出结果。

该级别不需要恢复数据库，优先作为第一选择。

### Level 2：回退应用代码

适用：新版本前端、后端或规则实现存在缺陷。

步骤：

1. 停止后台服务和未完成审核任务；
2. 记录失败日志、任务状态和当前 commit；
3. 将部署代码回退到上一版已验证 commit 或执行已审核 PR 的 revert；
4. 保留数据库新增字段，旧代码只读取兼容字段；
5. 启动旧版本并执行健康检查、产品选择、关键词查询和广告建议读取；
6. 仅对未完成任务执行增量重试，不自动重跑已完成任务。

### Level 3：恢复数据库备份

适用：迁移破坏数据、数据库损坏、人工锁定字段被覆盖，或 Level 1/2 无法恢复。

步骤：

1. 停止后端和前端写入；
2. 将当前数据库改名为带时间戳的隔离文件，禁止直接删除；
3. 先在临时恢复目录打开备份并执行完整性检查；
4. 完整性检查通过后，再将备份复制到应用配置指定位置；
5. 如果备份使用 WAL，必须同时恢复匹配的 `-wal`、`-shm` 文件，不能混用不同时间点的侧车文件；
6. 启动上一版应用并完成恢复后验证；
7. 将隔离的故障数据库、日志和校验结果保留到问题关闭后，再按保留策略处理。

## 6. Windows 恢复操作示例

以下命令中的路径必须替换为已确认的实际文件路径，不能使用工作区根目录或宽泛通配符作为删除目标：

```powershell
# 示例：先确认服务已停止，再建立带时间戳的隔离目录
$backupRoot = 'D:\KeywordGrove\backups\2026-09-04-ad-rules'
$dbPath = 'D:\KeywordGrove\data\keyword-grove.db'
New-Item -ItemType Directory -Force -Path $backupRoot | Out-Null
Copy-Item -LiteralPath $dbPath -Destination (Join-Path $backupRoot 'keyword-grove.db')
if (Test-Path -LiteralPath "$dbPath-wal") { Copy-Item -LiteralPath "$dbPath-wal" -Destination (Join-Path $backupRoot 'keyword-grove.db-wal') }
if (Test-Path -LiteralPath "$dbPath-shm") { Copy-Item -LiteralPath "$dbPath-shm" -Destination (Join-Path $backupRoot 'keyword-grove.db-shm') }
```

复制完成后必须检查备份文件存在、大小合理并可以被 SQLite 打开。不要在校验前执行 `Remove-Item`，也不要将备份文件直接覆盖正在运行的数据库。

## 7. 回滚后验证

### 7.1 数据一致性

- 产品数量与回滚前基线一致；
- 当前产品的关键词数量、来源 ASIN 数量和导入批次一致；
- 人工锁定数量、动作、备注和分类未减少；
- 关键词历史指标和导入记录可查询；
- 没有出现 `NaN`、负数总量或虚构的竞品 ASIN。

### 7.2 业务规则

- `boxwood wreath` 在满足门槛时仍可作为广泛候选；
- `boxwood wreath for front door` 可作为精准候选；
- `room decor` 可作为否定精准，`room` 不得自动成为否定词组；
- `3/20`、`5/20` 的泛词不得进入精准或广泛；
- 否定词组必须显示来源否定精准词和受影响关键词；
- 冲突词不进入四类最终下载清单；
- 每个产品广泛词条数量不超过配置上限，除非明确标记为候选。

### 7.3 工程验证

- 后端编译、`pip check` 和后端测试通过；
- 前端 TypeScript、Vitest 和 Vite production build 通过；
- 规则版本和回滚 commit 记录完整；
- 公开仓库脱敏扫描通过，没有真实 SellerSprite 文件、数据库、日志或 API Key；
- AI 审核没有在回滚过程中产生新的非必要调用。

## 8. 事故记录要求

每次回滚必须记录：

- 触发时间、发现人和影响产品；
- 触发条件和用户可见现象；
- 应用版本、规则版本、Git commit；
- 执行的回滚级别和具体步骤；
- 数据库备份位置及完整性校验结果；
- 回滚前后数量对比；
- 是否产生 AI 调用或费用；
- 后续修复项和是否需要新的 PR。

回滚完成不等于问题关闭。修复必须重新走测试、脱敏检查和独立 PR，不能直接在回滚分支上覆盖发布。

## 9. 实现 PR 合并门槛

- [ ] PR 包含迁移说明、兼容性说明和回滚说明；
- [ ] v1/v2 功能开关可用，默认状态经过确认；
- [ ] 数据库备份与恢复演练完成；
- [ ] 影子结果与历史样本完成对比；
- [ ] 低覆盖、低搜索量、动作冲突和否定词组误伤测试通过；
- [ ] 前端、后端、构建和脱敏扫描全部通过；
- [ ] 合并前没有未解释的人工锁定字段变化或关键词数量变化。
