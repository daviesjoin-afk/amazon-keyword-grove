## 2. 背景与问题

SellerSprite 关键词反查表同时包含高意向长尾词、产品核心词根、车型/零件号、竞品词和泛词。历史广告表体现了较稳定的人工工作方式：

- 正向投放只有“精准”和“广泛”，不使用正向词组匹配；
- 广泛投放保留少量产品级词根，精准投放承接长尾、车型和零件号；
- 完整的不适配搜索词使用否定精准；
- 只有整个词根在当前产品下都不适配时，才使用否定词组；
- 低月搜索量和低竞品覆盖率的词不应为了增加数量而进入精准投放。

当前实现已经具备竞品 ASIN 覆盖率、月搜索量门槛、广泛核心词限制和否定词组二次检查，但仍有以下风险：

1. 核心词根默认推导较窄，可能漏掉同义产品根词和高价值短组合；
2. 否定词组只允许双词根，无法覆盖历史表中大量经过人工确认的单词根；
3. 同一关键词在历史表中可能同时出现在广泛、精准或否定栏，缺少明确冲突状态；
4. 车型、品牌和零件号在不同产品中的含义不同，不能使用全局词根否定；
5. AI 返回的正向判断不得越过竞品覆盖率和月搜索量的硬门槛。

## 3. 目标

### 3.1 产品目标

1. 让规则输出与运营人员的历史判断方式一致，且每个结果可解释、可复核、可回滚。
2. 以月搜索量为审核队列第一排序条件，再使用竞品覆盖率、内置规则和语义分数判断动作。
3. 广泛投放最终控制在每个产品 5–10 个词条，精准投放承接明确长尾。
4. 让否定精准和否定词组形成“完整搜索词 → 词根扩展”的两级审核链路。
5. 在不增加误否定的前提下，降低无效人工复核数量。

### 3.2 不在本次改造范围内

- 不连接或操作 Amazon Ads；
- 不自动创建广告活动、调价或执行否词；
- 不把正向词组匹配加入投放建议；
- 不把历史广告表未经清洗的列直接作为自动标签；
- 不删除已有关键词、来源 ASIN、指标历史或人工锁定结果；
- 不在本次改造中更换 AI 服务商或默认模型。

## 4. 历史表基线

排除花环两张表后，对历史广告页的关键词列进行标准化、去重，并排除 ASIN、辅助字段和表内中文备注。结果用于规则设计，不作为无条件的训练标签。

| 指标 | 结果 |
|---|---:|
| 广泛投放 | 59 个单元格，51 个去重词条 |
| 精准投放 | 320 个单元格，288 个去重词条 |
| 否定词组 | 281 个单元格，249 个去重词条 |
| 否定精准 | 1,053 个单元格，908 个去重词条 |

主要观察：

- 广泛投放多数产品只有 3–6 个词条；「垫块广告-10」有 20 个候选，且出现与否定精准重叠，应视为历史冲突样本；
- 精准投放约 94% 的去重词条为三词及以上，主要是长尾、车型、年份、零件号和适配组合；
- 否定词组约 90% 为单词根，约 10% 为双词根，没有三词以上词组；
- 否定精准约 79% 为三词及以上的完整搜索词；
- 至少 7 个历史投放页出现同一标准化关键词同时位于多个动作栏，必须先进入冲突复核。

## 5. 术语与数据定义

### 5.1 相关性

相关性使用当前产品的竞品 ASIN 覆盖率表示，例如 `5/20`。它与 AI 语义分数分开保存：

- `competitor_coverage`：产品级覆盖率，作为投放安全门槛；
- `relevance_score`：0–100 的规则/语义辅助分，用于解释和排序；
- `monthly_search_volume`：月搜索量，用于审核队列排序和投放价值门槛。

AI 语义分数不得覆盖低竞品覆盖率的硬性限制。

### 5.2 词根

词根是可以独立用于发现搜索组合的产品核心短语。词根分为：

- 主核心词根：产品标题和五点明确表达的产品类型；
- 同义/别名词根：标题、五点和人工确认的产品同义表达；
- 适配词根：车型、年份、零件号等，仅在产品资料确认后启用；
- 保护词根：可能误伤有效组合的通用词、场景词或合法适配词；
- 排除词根：产品明确不支持的品牌、车型、部件或用途。

### 5.3 规则动作

系统最终只允许一个最终动作：

- `exact`：精准投放；
- `broad`：广泛投放；
- `negative_exact`：否定精准；
- `negative_phrase`：否定词组；
- `observe`：观察/暂不投放；
- `manual_review`：资料不足或存在冲突，等待人工确认。

## 6. 目标审核流程

```text
导入与标准化
  → 月搜索量降序排队
  → 竞品覆盖率硬门槛
  → 内置规则预审
  → AI 语义复核
  → 动作冲突消解
  → 产品级否定词组误伤检查
  → 持久化最终草稿与证据
```

排序键固定为：

1. 月搜索量降序；
2. 竞品 ASIN 覆盖率降序；
3. 语义/规则分数降序；
4. 关键词 ID 升序，保证同分时稳定。

## 7. 详细规则

### 7.1 投放资格硬门槛

默认配置保持当前基线：

- 竞品覆盖率低于 30% 时，不得进入精准或广泛；
- 月搜索量低于 300 时，不得进入精准或广泛；
- 低门槛词若没有明确不适配证据，进入观察，不自动否定；
- 明确冲突或明确不适配的完整搜索词，可以进入否定精准，即使搜索量较高。

阈值必须配置化，后续允许按产品、站点和类目调整，但每次调整都要记录规则版本。

### 7.2 广泛投放

广泛投放仅从产品级核心词根池中选择，正向投放不产生词组匹配。

候选条件：

1. 词条包含产品核心锚点或经过人工确认的同义根词；
2. 竞品覆盖率和月搜索量均达到门槛；
3. AI 没有明确判定为泛词、过宽或不适配；
4. 不包含未确认的车型、品牌或竞品词；
5. 按月搜索量、覆盖率和语义分排序后，每个产品保留 5–10 个词条；
6. 每个词条建议为 1–3 个英文单词，长尾完整组合转入精准投放。

广泛词超出 10 个时，不自动全部导出，保留候选并标记“超出广泛词条上限”。

### 7.3 精准投放

精准投放优先承接：

- 三词及以上的明确长尾；
- 车型、年份、适配位置和零件号组合；
- 产品用途明确且不存在泛化风险的查询；
- 已有出单或高意向证据的关键词。

产品核心根词本身优先进入广泛候选，不因包含核心词就自动复制为精准，除非人工锁定或产品配置明确要求双投。

### 7.4 否定精准

满足以下任一条件时，建议否定完整搜索词：

- 明确属于其他产品类型、用途或部件；
- 命中产品排除词、竞品品牌或不兼容车型；
- AI 和内置规则均认为完整查询不适配；
- 词根仍可能出现在有效组合中，不能扩大为词组否定。

低覆盖率本身不是否定精准理由；没有明确冲突时应为观察。

### 7.5 否定词组

否定词组必须在否定精准审核完成后按产品执行二次审核。单词根和双词根均可成为候选，但安全条件不同。

共同条件：

1. 候选词根至少命中两个已审核的否定精准搜索词，或由人工明确指定；
2. 当前产品中所有包含该词根的关键词均完成审核；
3. 不存在精准、广泛或中高相关的有效扩展；
4. 不命中产品主核心词、适配词或保护词；
5. 保存受影响关键词、保护关键词、审核分数和生成原因。

单词根额外条件：

- 默认禁止 `room`、`home`、`decor`、`rv` 等高误伤通用词；
- 车型、品牌、部件单词只有在当前产品资料确认不适配时才允许；
- 无法证明所有扩展均不适配时，降级为否定精准或观察。

例如：`room decor` 可以否定精准，但 `room` 不应自动成为否定词组；`rod` 是否可否定词组则必须结合当前产品的水箱阀资料和所有扩展词判断。

### 7.6 冲突消解

同一标准化关键词只能保留一个最终动作。优先级如下：

1. 人工锁定结果；
2. 明确不适配的否定精准；
3. 通过全部误伤检查的否定词组；
4. 选入产品级广泛词根池；
5. 明确长尾精准投放；
6. 观察；
7. 人工复核。

如果一个词同时命中正向和否定动作，不能静默覆盖，必须保存 `conflict_actions`、冲突来源和最终选择理由。冲突样本不得参与自动规则学习。

## 8. AI 语义审核约束

AI 只负责补充语义判断、理由和置信度，不负责突破本 PRD 的硬门槛。

请求中必须提供：

- 产品名称、标题、五点、核心词根、保护词根和排除词；
- 竞品覆盖率和月搜索量；
- 内置规则动作及理由；
- 词根受影响关键词列表（用于否定词组审核）。

响应必须包含每个关键词一次且仅一次的决策。无效响应、缺失 ID、非法动作或超时批次保持待审核，不得默认为投放。

## 9. 持久化与可追溯性

实现阶段建议新增或补充以下字段，采用可回滚的可空字段迁移：

- `rule_engine_version`；
- `rule_action_before_semantic`；
- `final_action_source`；
- `root_candidate_type`；
- `root_source`；
- `protected_terms_json`；
- `conflict_actions_json`；
- `negative_phrase_eligible`；
- `negative_phrase_evidence_json`。

已有 `manual_locked`、人工动作、人工备注、来源 ASIN、指标历史和语义审核结果不得被规则重算覆盖。

全量重新审核必须显式选择并记录新规则版本；增量审核只处理未完成或签名已失效的记录。

## 10. 页面与导出要求

- 广告建议页继续只显示精准投放、广泛投放、否定精准、否定词组和观察；
- 每个建议显示月搜索量、竞品覆盖率（如 `5/20`）、语义分、理由、风险和审核状态；
- 冲突词单独显示“动作冲突”，不得混入四类下载清单；
- 广泛投放超过 10 条时显示超限提示；
- 否定词组显示词根、来源否定精准词和受影响关键词数量；
- CSV 导出包含规则版本和最终动作来源，便于回溯。

## 11. 验收标准

### 11.1 规则验收

- `boxwood wreath` 在覆盖率和搜索量达标时可进入广泛候选；
- `boxwood wreath for front door` 进入精准，不因包含核心词自动进入广泛；
- `room decor` 可进入否定精准；`room` 不得自动进入否定词组；
- 覆盖率为 `3/20` 或 `5/20` 的泛词不得进入精准或广泛；
- 明确不适配的高搜索量完整查询仍可进入否定精准；
- 一个产品广泛词条超过 10 个时，超出的词条只保留候选；
- 同一关键词同时命中多个动作时，显示冲突并只保留一个最终动作；
- 否定词组生成前，所有受影响扩展均已完成审核，存在有效扩展则不生成词组否定。

### 11.2 数据与稳定性验收

- 增量导入不覆盖人工锁定字段；
- 刷新页面不重新调用已经完成的语义审核；
- 审核失败批次保持待审核，可通过增量审核重试；
- 规则版本变更前后均可查询建议来源和证据；
- 空产品、无关键词和缺失指标不会伪造竞品数量、审核进度或百分比；
- 真实 SellerSprite 文件、数据库、日志和 API Key 不进入公开仓库。

## 12. 分阶段上线方案

1. **基线阶段**：只读生成 v2 影子结果，与现有结果并排比较，不改变导出。
2. **小范围阶段**：选择一个已导入产品，开启 v2 广泛候选和冲突提示，人工确认后导出。
3. **扩展阶段**：逐个产品启用否定词组二次审核，持续监控误伤和人工退回率。
4. **默认阶段**：连续两个批次满足验收指标后，才将 v2 设为默认规则版本。

每个阶段都必须保留 v1 结果、规则版本、数据库备份和可执行回滚路径，详见《广告建议规则优化回滚预案》。
